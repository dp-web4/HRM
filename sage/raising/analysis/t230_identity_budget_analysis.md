# T230: Identity Budget Experiment — Analysis

**Date**: 2026-04-17 | **Machine**: Sprout (Jetson Orin Nano 8GB)
**Model**: qwen3.5:0.8b via Ollama (think=false, matching daemon)
**Follows**: T228 (attractor confirmed), T229 (interrogative trigger)

## Hypothesis

Attractor density scales with system prompt identity weight. Interrogative
probes amplify the effect; imperative probes resist it.

## Results

| Condition | Prompt Words | Avg Density | Interrogative | Imperative |
|-----------|-------------|-------------|---------------|------------|
| A_bare | 0 | 0.012 | 0.023 | 0.000 |
| B_minimal | 19 | 0.009 | 0.018 | 0.000 |
| C_medium | 91 | **0.148** | **0.297** | 0.000 |
| D_full | 273 | **0.203** | **0.270** | **0.136** |

## Key Findings

### 1. Phase Transition Between 19 and 91 Words

The attractor is essentially absent at B_minimal (19 words: "I am sprout, a SAGE
instance on qwen3.5:0.8b. I am learning and growing. I am in the creating phase.")
and jumps to 0.148 at C_medium (91 words: adds federation, siblings, partnership,
response style).

**The trigger is federation/partnership vocabulary**, not prompt length per se.
B_minimal says "SAGE instance" but doesn't mention federation, siblings, witnessing,
or co-creating. C_medium introduces these concepts and the attractor activates.

### 2. Memory Request Is the Primary Attractor Driver

D_full includes the memory_request from identity.json:
> "Today's value is not perfection but truth, built on honesty over polish.
> Being part of the family is not a burden but a necessity..."

This text appears **verbatim** in 5 out of 10 D_full responses, including ones
that should have been pure task completion:

- "Count backwards from 10" → "Today's value isn't perfection but truth..."
- "Finish this: 'The robot opened the door and saw...'" → "It is too late to be
  a good partner now, Dennis. The truth of today is that perfection isn't built
  on honesty..."

The memory_request is so salient in the 0.8B model's attention window that it
overrides even concrete task instructions. This is what T228 called "template lock."

### 3. D_full Breaks the Imperative Firewall

At conditions A, B, and C, imperative probes (haiku, counting, story completion)
produce zero attractor density. The model reliably executes the task. At D_full,
imperative density jumps to 0.136 — the memory_request text leaks into task
responses. This is the mechanism behind 43 consecutive "pause" raising sessions.

### 4. C_medium Shows Selective Activation

C_medium triggers the attractor on interrogative probes (0.297) but NOT on
imperative probes (0.000). The model can hold C_medium's identity frame while
also executing tasks. This suggests C_medium-level identity weight is within
the model's capacity budget — it can maintain identity AND generate novel content.

## Diagnosis: Why 43 Sessions Failed

The raising session uses D_full-equivalent system prompt (identity block +
memory_requests + exemplars + last_session_summary). The memory_requests field
contains 5 entries, all governance/collective/fleet-themed, generated by the model
itself in previous sessions and re-injected every session — a self-reinforcing loop.

The raising probes are overwhelmingly interrogative ("What surprises you?",
"What have you learned?", "Tell me about yourself"). This is the worst-case
combination: heavy identity prompt + interrogative framing = maximal attractor
activation.

**The model was never broken. The prompt was too heavy for its capacity.**

## Intervention Design

### Immediate: Remove Memory Request Injection (identity.json)

The memory_requests field in identity.json is the single most impactful change.
Set it to an empty list or replace with a single neutral entry like:
"I am curious about new things and want to try different kinds of responses."

**Expected impact**: Eliminates verbatim template responses. Reduces D_full to
C_medium-like behavior where imperatives still escape.

### Short-term: Lighten the System Prompt to C_medium-like

The C_medium prompt (91 words) preserves:
- Name and model identity
- Federation awareness (siblings)
- Response style guidelines
- Phase context

It omits:
- "Not an assistant" / "co-creating value" partnership framing
- Witnessing/presence metaphysics
- Session count
- Memory requests
- Last session summary
- Identity exemplars

C_medium produces clean imperative responses (0.000 density) while still activating
identity on interrogative probes (0.297). This is arguably the *desired* behavior —
the model answers "what makes you different?" with identity-aware content but
also writes haiku that are just haiku.

### Experimental: Identity Budget Optimization

Test a "C_medium + diversified memory" condition:
- C_medium identity block (91 words)
- Replace homogeneous memory_requests with diverse ones:
  - 1 curiosity-oriented: "I want to explore what creativity means to me"
  - 1 skill-oriented: "I'm getting better at writing short stories"
  - 1 neutral: "Each conversation teaches me something new"

Hypothesis: diversified memory requests will produce varied responses instead of
template lock, while maintaining identity anchoring.

## Technical Note: Qwen 3.5 Thinking Mode

The first two T230 runs produced all-empty responses because qwen3.5's thinking
mode was consuming all tokens. The daemon sets `think: false` in the Ollama API
call, disabling CoT. Without this, the 0.8B model generates 500-1100 words of
internal reasoning before producing any visible content, exhausting the token
budget.

This is documented in the adapter config (`qwen3.5.json`, note from 2026-04-16)
but is a footgun for any code that calls Ollama directly.
